A vertical cross-section survey of Hive City 001, Terra. Scroll down 45.2 kilometres.

Open `index.html` in a browser. No server, no build step, no dependencies.

## Hosting it

The whole thing is static, so GitHub Pages serves it unchanged: push, then
**Settings → Pages → Deploy from a branch → `main` / root**. A `.nojekyll` file is
included so Pages does not strip files beginning with an underscore.

Over `http(s)` the loader fetches `data/*.json` directly; over `file://` it falls
back to `data/embedded.js`, the generated mirror. Both paths work, so the same
commit runs from a hard drive or from a URL with no changes.

## What it is

A single-page interactive descent through an Imperial hive city, from the cathedral
spires above the datum to whatever is underneath the part the Administratum admits
exists. Seven architectural strata, ~25 clickable structural records, 22 narrative
interrupts, procedurally generated architecture, evolving palette, procedural audio,
and an interface that stops being reliable somewhere below -30,000 m.

## The stratum dossier

Open by default (press `D` to hide). Two halves, both driven by depth:

**Nine instrument readings** — population density, mean lifespan, tithe compliance,
Administratum control, breathable air, ambient temperature, surface light, vox
integrity, and load borne. These are defined per stratum in `terra.json` and
interpolated across the *whole* span of each layer, so they tick continuously rather
than jumping seven times in 45 km. They tell their own story: density peaks in the
Lower Hive and then collapses, lifespan falls 84 → 22 years, temperature climbs to
47 °C in the manufactorum belt, *drops* in the underhive away from the furnaces, then
climbs again to 74 °C from geothermal heat.

The degradation rule is deliberate. Physical instruments keep working all the way
down — temperature, air and mass are still read correctly at 45 km. It is the
*records* that fail. So below the Forgotten Levels the bureaucratic rows go to
`UNSURVEYED` and then `NO DATA` while the sensor rows carry on reporting.

**57 field notes**, spread from +1,100 m to -44,800 m, surfacing as you pass each
depth. These are the explanatory layer: how a hive city is actually built and
inhabited, why nothing is ever demolished, what corpse-starch grades mean, why the
wealthy live at the top (the view, but mostly the air), what "gang" means as a legal
category, who counts the people nobody counts. Largest gap between notes is 1,600 m.

## Backdrop plates

Behind the city, on a plane slower than the far architecture, sit 23 copperplate
etchings. They are **generated, not downloaded** — `js/engraving.js` draws them from
the archive seed, so they need no network, no files and no licence, and they work
on a locked-down machine.

Eight compositions, in the vocabulary of the Carceri:

| | |
|---|---|
| `vault` | Receding barrel vault — a corridor continuing past where it should have ended |
| `arcade` | Tiered arcades — load-bearing substructure, endlessly repeated |
| `stairs` | Dog-leg flights crossing a shaft, serving nothing in particular |
| `windlass` | Great wheel, drum and rope on a braced timber frame |
| `shaft` | A timbered shaft with ladders and staging |
| `cavern` | Branching subterranean channels cut through rock |
| `engine` | Beam engine and gear train, purpose unstated |
| `monument` | A monument standing in an otherwise empty plate |

**How the drawing works.** An etcher cannot lay down grey — tone comes from line
density alone. So there are no fills anywhere in this file: parallel rulings for a
light wash, crossed rulings for shadow, and strokes laid *along* the form for
curvature, which is what makes a vault read as round rather than as a set of
concentric lines. Hatching is generated as infinite rulings and trimmed with
Liang–Barsky clipping, which is far cheaper than a clip path per field, then every
field collapses into one `<path>` — a fully hatched vault costs four DOM nodes.
Lines are also bitten slightly short and irregular at the ends, because a real
plate's lines are.

Each plate carries a line unit derived from its own width, so a 1,700 m plate and a
900 m plate are drawn with proportionate pen weights. Three stroke opacities stand
in for three pen weights: contour, fine detail, and tone.

`tools/preview/_engraving-sheet.png` is a contact sheet of all eight.

### Optional: real historical plates

`data/plates.json` also describes 18 genuine public-domain engravings that fit the
same slots. They are not bundled; `node tools/fetch-plates.mjs` (or double-clicking
`fetch-plates.cmd`) downloads them from Wikimedia Commons into `art/`. If they are
installed, the generated plate at that depth stands down in favour of the real one.
Each is preflighted with an `Image()` before any element is created, so a missing

Every artist died more than 70 years ago and every work was published between 1556
and 1914, so all are public domain worldwide. The digitisations come from Wikimedia
Commons. Doré's plates were wood-engraved by Stéphane Pannemaker for *London: A
Pilgrimage*, text by William Blanchard Jerrold; Agricola's woodcuts were cut by Hans
Rudolf Manuel Deutsch (1525–1571) and Zacharias Specklin (1530–1576).

These are also the acknowledged *influences* on the generated plates — the drawing
conventions borrowed are Piranesi's impossible vaulted interiors and arcaded Roman
substructures, the shaft-and-ladder plates of the Renaissance mining treatises, the
branching subterranean channels of the old cosmographies, and the beam engines of
industrial-revolution engineering prints. Influences on convention, not sources that
have been copied.

**Attribution is in the app, not just here.** Press `P` for the full credits sheet,
generated from the same manifest the renderer reads — the credits cannot drift from
what is on screen. And whenever a plate is visible, the stratum dossier names its
artist, title and year. `tools/fetch-plates.mjs` additionally writes
`art/CREDITS.txt` using the licence metadata Commons reports at download time, rather
than anything asserted by this project.

**How the bitmaps are rendered.** An engraving is white paper and black ink, which is
useless as a backdrop until you throw the paper away. `filter#fPlate` is a single
`feColorMatrix` that flattens RGB to a constant and sets `alpha = 1 − luminance`, so
white paper becomes fully transparent and only the linework survives — rendered in a
colour interpolated from the current stratum, the same `--plate-ink` the generated
plates stroke with. A radial mask kills the plate mark so it never reads as a pasted
rectangle, and the filter region is pinned to the bounding box (otherwise the alpha
inversion would flood the whole filter area with solid colour).
`tools/preview/_filter-check.png` shows the effect isolated.

Deliberately excluded: **Hugh Ferriss**'s *Metropolis of Tomorrow* (1929), which
would fit beautifully but is public domain only in the US — it remains in copyright
in the EU until 2033.

## How it works

**Depth.** An invisible 30,000 px spacer owns the scrollbar. Scroll position maps to a
target depth; the camera eases toward it every frame, so the city has weight.

**The cross-section.** One `<svg>`, four parallax planes. World coordinates are
*metres* — x = 0 is the hive's central axis, +y is down. Each plane is a `<g>` whose
`translate + scale` transform is rewritten once per frame; the browser composites that
on the GPU regardless of how much geometry is inside.

**Virtualisation.** The city is cut into 220 m chunks, composed on demand as SVG source
strings and inserted with a single `innerHTML` write, then discarded once they leave a
margin around the viewport. Peak load is around 3,000 SVG nodes out of a city that
would otherwise be several hundred thousand.

**Continuity.** Load columns, conduit bundles and lift shafts have fixed x positions for
the entire 45 km, so chunk seams are invisible and the eye reads one structure. Spires
above the datum are defined as a width-versus-depth profile, and each chunk draws only
its own slice — a 1.8 km tower costs nothing extra.

**Determinism.** Everything derives from `seed` in the city JSON via a hashed
mulberry32. The city is identical on every load and never repeats itself.

**Progression.** Each stratum carries a palette and an environment vector (fog, grime,
dust, sparks, flicker, noise, glitch, vignette). Both are interpolated across stratum
boundaries and written to CSS custom properties, so the entire city re-tints with a
handful of variable writes. Transparency uses `fill-opacity` rather than `opacity` —
element opacity would force an isolation layer the size of a kilometres-tall shape.

**Audio.** Fully synthesised: filtered brown noise for wind and ventilation, detuned
saws for the machine drone, 50 Hz + harmonic for the electrical hum, enveloped bursts
for clangs, drips, bells and alarms. The mix crossfades with depth. If Web Audio is
unavailable, every entry point is a no-op.

## Adding a city

1. Copy `data/necromunda.json` and fill in `layers` (each with `palette`, `env` and
   `readings`), `structures`, `events`, `notes` and `scaleLadder` to the shape used by
   `data/terra.json`.
2. Set `available: true` for it in `data/cities.json`.
3. Run `node tools/build-embed.js`.

No engine changes are required. Locked cities in the registry display their `denial`
text instead of loading.

## Verification

```
npm install                   # jsdom + resvg, dev-only
npm test                      # boots in jsdom, drives a full 46 km descent,
                              # opens every record, fires every event, checks
                              # the notes are reachable and the readings trend
                              # with depth, verifies every plate author is
                              # credited, confirms determinism
npm run preview               # writes PNG stills of the cross-section
npm run embed                 # regenerate data/embedded.js after editing JSON
```

Both dependencies are dev-only — **the site itself has no dependencies whatsoever**
and never loads anything from the network.

`.github/workflows/survey.yml` runs the smoke test on every push and additionally
fails the build if `data/embedded.js` has drifted out of sync with `data/*.json`,
which is the one way this project can silently break.
